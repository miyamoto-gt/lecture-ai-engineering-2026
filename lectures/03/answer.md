# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：用語集や講義の要約をツールで参照するため、講座に固有の用語や講義内容について根拠のある回答ができる
- `--trace` で見えたツール呼び出し（ツール名と引数）：search_glossary({'query': 'ハーネス'})
- 1つの質問での LLM 呼び出し回数（`requests`）：2（ツールを呼ぶと決める回と、結果を見て回答する回）
- 追加したツールと、docstring に書いた説明：`make_quiz(lecture: int) -> str`。
docstring には「指定した回の用語から1つを選び、確認問題と答えを返す。『第2回の確認問題を出して』のように、復習用の問題を求められたときに使う」と書いた。INSTRUCTIONS には make_quiz の指示がないが、docstring だけでモデルに選ばれ、`make_quiz({'lecture': 2})` と整数で呼ばれた。ツールは答えも返したが、INSTRUCTIONS の「答えそのものは書かずヒントで導く」に従い、モデルは答えを伏せて問題だけを出した。

## 宿題

- 取り組んだレベル：発展（Google ADKで作り直して比較）
- やったこと：

  2. ADK 2.14.0 を使い、`PYTHONPATH=. uv run --with google-adk adk run adk_agent/glossary_agent` と `adk web adk_agent` で実行した
  3. 演習版（`--trace`）とADK版（`adk web` のイベント、ログ）に同じ質問2つを投げて比べた
     - Q1「ハーネスとはなんですか」
     - Q2「第3回の講義の要点と、その中に出てくる『構造化出力』の意味を教えて」
- 結果：

  処理速度は、`app/` を変えずにADK版を同じ区間で測る方法がなかったため比較していない。

- 気づき・疑問：
  - なぜ振る舞いが同じになったか：ツールを呼ぶかやどれをどんな引数で呼ぶかを決めるのはモデルであるから。その判断材料（`INSTRUCTIONS`、ツールの名前・docstring・引数の型、ユーザーの質問）は、両方の版で `app/agent.py` と `app/tools.py` から読み込んでおり同じだった。そのため、ハーネスを替えても呼ぶツール・引数・回数は同じになった。回答の細部の違いは、ハーネスではなくモデルの出力の揺れによるものと考えられる。
  - ハーネスの違いが効くところ：
    - メモリの管理：ADKは会話を `session.db` に自動保存する。同じ会話で続けて質問したところ、前の質問の履歴がコンテキストに入り、要点の項目数が変わった
    - 安全性の確保：Pydantic AIはモデルを実行時に渡す設計で、テストでは偽のモデル（TestModel）に差し替えられる。traceは講座の自作だったが、ADKは `adk web` でイベントやツールの関係図を確認できた
    - ツールの実行：Pydantic AIは作成後に `tool_plain()` で1つずつ登録し、ADKは `tools=[...]` でまとめて渡す
  - 疑問：ツールを `async def` にしたら、ADKで2つのツールの実行は並列になるか。docstringを変えたら、2つのハーネスで差が出るか
